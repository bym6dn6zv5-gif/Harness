# 第 1 课：先把六种“记住”分开

## 场景：你说“以后 Python 文件都放到 D 盘”

这句话先进入当前对话，模型在本轮能看到它。
如果没有发生持久化，下次启动时这句话可能不在输入中。
如果把它存为长期事实，下次加载时模型才可能再次用到它。
如果只是写了“我记住了”，既没有工具调用也没有写入证据，就不能判断保存成功。

| 内容 | 解决的问题 | 当前 Hermes 对应 | 本课程项目对应 |
| --- | --- | --- | --- |
| 当前消息列表 | 这轮在讨论什么 | 活跃 messages 与发送给模型的输入 | lesson03 的 history |
| 长期精选事实 | 下次仍应知道什么 | MEMORY.md、USER.md | 本专题离线实验 |
| 完整历史与检索索引 | 上次的依据在哪里 | state.db、session_search | JSONL 轨迹及将来检索器 |
| 上下文摘要 | 输入太长后怎样继续 | 压缩与摘要路径 | lesson05 的简化视图及后续摘要 |
| 可复用步骤 | 某类工作应该怎样做 | skills 相关模块 | 将来的任务操作说明 |
| 任务检查点 | 中断后从哪里继续 | 会话状态及不同恢复路径 | lesson09 的 SQLite 检查点 |

技能更接近可复用操作步骤；用户偏好更接近事实。这里是用途对比，不声称它们在项目中完全互斥。
不要把日志、摘要和长期记忆都叫一个 memory，然后用一个“保存成功”覆盖六种不同保证。

## 默认文件记忆

在默认 profile 下，两份小文件通常位于 ~/.hermes/memories/：

- MEMORY.md：环境事实、项目约定、经验等。默认容量 2200 字符。
- USER.md：用户偏好、沟通方式等。默认容量 1375 字符。

它们可配置，容量按字符计算，不是精确 token 数，也不是费用上限。
在 Python 中 len("中文") 是 2；UTF-8 字节数和某模型 token 数又是其他指标。
多条内容用换行、§、换行分隔，分隔符也占内容预算。
profile 改变后，目录也改变；“写到 work profile，读默认 profile”会表现为失忆。
这里只讲路径规则，不读取任何真实个人记忆。

## 从启动到模型看见

1. agent_init.py 的 _init_memory 读取配置与启用状态。
2. MemoryStore.load_from_disk 解析文件，按首次出现顺序去除完全相同条目。
3. 加载时构造 _system_prompt_snapshot；威胁规则命中的内容在提示快照中以阻断占位显示，
   原始条目仍留在存储中供检查。
4. system_prompt.py 的 _memory_parts 按开启的 target 调用 format_for_system_prompt。
5. 构造出的文本进入提示词；模型依据这次输入中的文本生成后续回答。

~~~mermaid
flowchart LR
  A[磁盘 MEMORY.md 与 USER.md] --> B[加载与解析]
  B --> C[会话提示快照]
  C --> D[本次模型输入]
  D --> E[模型回答或提出 memory 调用]
  E --> F[宿主程序校验并写磁盘]
  F --> A
~~~

## 最关键的时间差：磁盘与提示快照

在通常的同一提示快照期间，memory 工具写入会更新磁盘与活跃条目，
不会直接改写已经冻结的提示块；当前回合仍能通过工具结果知道写入是否成功。
新的会话重新加载后，会得到新快照。这样减少频繁变动对提示前缀缓存的影响，
是否实际命中缓存仍取决于模型服务和其他输入。

要特别读源码而不只背文档：文档把快照描述成会话内永不变化，
但该提交的 system_prompt.invalidate_system_prompt（815—832）明确在上下文压缩后的重建边界重新加载记忆。
所以更准确的说法是：**普通写入不直接刷新当前快照；新会话和指定的提示重建边界可能刷新。**
不能据此推出任意时刻修改文件都会立刻生效。

另一个细节：文档说工具响应展示实时状态，但该版本 _success_response 返回 usage、
entry_count、完成标记等，刻意不回显整份条目；某些错误才带当前条目或匹配内容。
“有实时结果”不等于“每次成功都把全部记忆重新放进上下文”。

## 纸上实验

开始时磁盘 A，快照 A。当前会话写入 B：

| 时刻 | 磁盘 | 当前快照 | 当前模型能凭什么知道 B |
| --- | --- | --- | --- |
| 写入前 | A | A | 尚无 B |
| 工具已成功返回 | A+B | A | 工具回传和当前对话 |
| 新会话重新加载 | A+B | A+B | 新提示快照 |
| 压缩触发上述重建路径 | A+B | 重新加载得到 A+B | 重建后的输入 |

作业：把“程序重启”和“逻辑新会话”画成两个开关。
网关可能恢复同一个会话，重启机器并不必然创建新会话。
验收：不看表解释“保存了但另一已运行会话没看到”至少两个可能原因。
