# 第 3 课：历史怎样找回来

## 小笔记回答“记得什么”，历史回答“依据在哪里”

小笔记容量有限，只保留高度精选的事实。
例如“当前项目在 D 盘”适合小笔记；十几次路径修正、报错与测试输出适合会话历史。
模型需要原始细节时，通过 session_search 检索对应会话和消息，
再把检索结果作为工具结果带进本轮输入。
保存在磁盘但未进入本轮输入的内容，不会被模型自动感知。

本地默认历史数据库入口为 Hermes home 下的 state.db。
session_search 在没有现成可用 DB 时尝试打开只读数据库句柄，结束时释放自己打开的句柄。
数据库不可用会返回错误，不能把“检索故障”当成“以前从没说过”。

## 同一个工具的几种使用方式

读 tools/session_search_tool.py 的 _dispatch（577—598）：

| 输入形状 | 路线 | 目的 |
| --- | --- | --- |
| 有 session_id 和 around_message_id | scroll | 围绕命中消息看邻近上下文 |
| 有 session_id | read | 阅读指定会话 |
| 无关键词 | list recent | 浏览最近会话 |
| 有 query | discover | 搜索、聚合并返回候选 |

示例为理解接口的伪调用，不需要安装 Hermes：

~~~json
{"query": "Harness 项目路径", "limit": 3}
~~~

得到会话标识和消息锚点后再调用：

~~~json
{"session_id": "从真实结果取得的id", "around_message_id": 123, "window": 5}
~~~

这里的 id 是占位示例，实际不得编造。
正确流程是“发现候选→读原文→检查时间与修正→回答”，不能把片段命中直接当成最新事实。
源码还处理会话 lineage、压缩后的旧消息、角色和时间筛选等；这些设计用于减少重复命中活跃上下文、
错读分支或忽略被压缩掉的信息。完整过滤细节是进一步阅读任务。

## 默认不是“所有消息都向量化”

本次核对的本地搜索代码使用 SQLite 全文检索与若干降级路线。
_describe_search_path 给出了可观察的路径名：

- 常规非 CJK 查询走 FTS5。
- CJK 扩展可用、查询符合条件时走 CJK 索引。
- 否则视词长与运行能力使用 trigram 或 LIKE 扫描。
- 索引陈旧等情况可能回退到规范消息表扫描。

中文“项目”只有两个字，trigram 单词长度条件可能不满足；CJK bigram 扩展就是为这类情况设计的。
扩展、索引状态与环境影响真实路线，不能承诺 Windows 或任意 SQLite 安装都有该扩展。
这次没有安装扩展或跑 Hermes 搜索性能测试。

FTS 是词项/文本检索，不等于 embedding 相似度。
关键词检索对同义表达可能漏召回；向量检索也可能返回语义接近但事实不相干的内容。
是否引入向量库，要用任务与实验说明，不能用“高级”替代效果。

## 外部记忆 provider

_init_memory 的可选外部 provider 与内置小文件可以并存。
该初始化路径为选择的外部实现创建 MemoryManager，加载、检查可用性并初始化。
默认小文件记忆不要求先配置第三方服务。
虽然 manager 中保留 builtin 相关抽象分支，不能因此推断默认文件存储必然通过一个独立 provider 插件运行。

MemoryProvider 定义可扩展职责，包括：

- system_prompt_block：给提示增加说明。
- prefetch / queue_prefetch：根据当前任务预取相关记忆。
- sync_turn：同步完成的回合。
- on_session_end、on_session_switch：会话边界上的提取与重绑定。
- on_pre_compress：压缩前通知或检查点。
- get_tool_schemas、handle_tool_call：额外查询或写入工具。

MemoryManager 负责调用和生命周期协调。它不保证所有 provider 都使用同一种数据库、向量、
提取模型、保留策略或一致性语义。本轮没有逐一审核 Honcho、Mem0、Hindsight 等实现，
所以不写“所有 provider 都自动得到完整长期理解”的结论。

外部 prefetch 超时返回后，底层守护线程仍可能在运行；有准入机制限制后续卡住调用。
超时不是线程硬终止。会话结束提取与 switch 还需要串行排序，
否则迟到的旧回合可能写进新的会话身份。
这些问题正好对应本课程的工具超时、恢复冲突和任务归属。

验收：讲清“保存成功、检索命中、答案使用了命中内容、答案事实正确”四项如何分别验证。
