# 第 4 课：后台复盘、上下文压缩和错误记忆

## 为什么不只等用户说“记住”

前台模型可以在执行任务时提出 memory 写入。
另一条路线是后台复盘：从对话中找出以后仍有用的偏好、经验或技能，再调用受控工具保存。
这是一次新的推理与工具执行流程，可能消耗 token 和费用；没有改变模型权重。

在 turn_finalizer 中，回复完成且未中断、未禁用后台复盘、满足记忆或技能触发条件时，才安排复盘。
初始化中的记忆 nudge_interval 默认值为 10，可配置；不要据此说“每条消息后都一定保存”，
更不能把工具迭代数与用户轮数不加区分。具体计数入口是后续追踪题。
run_agent._spawn_background_review 还检查 enabled、委派深度和是否需要等本地机器空闲等条件。

~~~mermaid
sequenceDiagram
  participant U as 用户
  participant A as 前台 Agent
  participant R as 复盘流程
  participant S as 文件存储或待审队列
  U->>A: 完成一项任务
  A-->>U: 交付本轮回答
  A->>A: 检查复盘开关与触发条件
  A->>R: 复制对话快照
  R->>R: 模型提取值得保留的信息
  R->>S: 受控 memory 调用
  S-->>R: 已保存 / 已暂存 / 拒绝
~~~

复盘使用结构化复制的快照，避免其清理过程修改前台活跃历史。
同模型复盘可能复用相同提示前缀；改用其他模型时可能构造更小的对话摘要。
文档中的特定节约比例不能直接当成你的账单预测。
当前课程的 100 元预算若将来接入此机制，必须包含前台、后台、摘要与重试全部模型调用。
本次没有开启任何复盘服务。

## 压缩为何容易造成失忆

输入太长时，Harness 可能用摘要替换旧消息。摘要是有损表示：
“用户在 D 盘有 Python 项目”可能遗漏精确路径、修正顺序、失败前提。
长期记忆保存稳定事实，历史数据库保留可查依据，摘要帮助当前会话继续，三者互补。
不能靠一句“压缩前写入记忆”就保证所有细节无损。

MemoryManager.on_pre_compress 区分旧版 best effort 通知与支持检查点 API 的 provider。
当 require_checkpoint 为真，需要支持对应版本且实际成功的 provider；
缺少能力或检查点失败时拒绝继续压缩，保留原始未压缩历史供调用方处理。
这不表示默认文件小记忆自带完整的压缩前可靠检查点。
是否要求检查点由配置和具体调用路径决定。

~~~mermaid
flowchart TD
  A[准备压缩旧上下文] --> B{要求可靠检查点?}
  B -->|否| C[按支持情况通知 provider]
  B -->|是| D{能力与执行是否成功?}
  D -->|否| E[拒绝压缩并报告]
  D -->|是| C
  C --> F[摘要与新的上下文视图]
  F --> G[相应重建边界刷新提示与文件记忆]
~~~

图是讲义抽象，不覆盖全部压缩重试、远端压缩和手动压缩分支。
重点是明确承诺：允许丢失什么、必须保留什么、失败时停止还是降级。

## 错误记忆会反复影响以后

历史里的一句猜测如果被存成确定事实，后续每次注入都可能扩大错误。
建议自己的实验条目带事实文本、来源事件、核验时间、适用项目和置信状态。
这些字段是本课程设计建议，当前 Hermes 小文件条目主要是文本，不会自动替你验证所有事实。

Hermes 有内容威胁模式扫描、加载快照过滤、审批门、文件锁和 profile 划分。
这些是多层保护，模式扫描不是完整语义证明。
外部召回上下文还通过 memory_context 构造包装；该版本包装措辞把它称为权威参考数据。
因此写入来源和 provider 的可信程度尤其重要，不能说“加了标签就能完全消除提示注入”。
召回旧内容也不能当成新的用户授权。

## “下次忘了”的定位顺序

| 现象 | 先找的证据 | 可能原因 |
| --- | --- | --- |
| 口头说已记住，文件没有 | memory 调用与真实写入结果 | 根本没调用；调用被拒绝 |
| pending 有，文件没有 | staged 与审批记录 | 只暂存了提案 |
| 文件有，另一个会话没看到 | profile、启动时间、提示快照 | 目录不一致或快照尚未刷新 |
| 检索不到已保存历史 | DB 错误、查询词、时间和角色过滤 | 搜索路线或索引问题 |
| 检索到了却答错 | 命中原文与本轮模型输入 | 旧事实、摘要误差、模型没采用 |
| 费用超出预期 | 前台与后台请求账本 | 复盘、摘要、重试未记账 |
| 恢复后重复做事 | 检查点提交点与副作用记录 | 执行完成但结果尚未提交 |

验收：每个“可能原因”至少设计一种能排除它的检查，不能只加长提示词。
