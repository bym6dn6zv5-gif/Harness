# 第 5 课：用实验检验是否理解

## 已准备的离线缩影

~~~powershell
Set-Location -LiteralPath 'D:\python\File of python\Harness开发'
& .\.venv\Scripts\python.exe -X utf8 -m mini_harness.memory_lab
& .\.venv\Scripts\python.exe -X utf8 -m pytest -q test_memory_lab.py
~~~

程序只在内存里操作虚构条目，不联网，不读取个人记忆，不写入 Hermes home。
它模拟“活跃状态与提示快照分离、唯一片段 patch、最终容量检查、批次回滚”四个机制。
它不实现落盘、文件锁、真实工具 schema、审批、SQLite 搜索、威胁扫描、后台模型或 Hermes provider。
跨进程恢复看第 9 天，真实存储机制看源码。不要把模拟输出写成 Hermes 实测。
实验也没有复刻原项目全部保护，例如“批次不能清空原本非空存储”的特殊限制；
它允许空列表终态，目的是单独观察批次的最终容量和回滚，不是替代原项目接口。

输出依次展示：初始快照；写入后快照未变；显式重新加载后可见新条目；
模糊 patch 被拒；批次第二步失败后状态仍相同。
源码中的 reload 是显式实验边界，不代表每回合自动刷新。

## 五项动手任务

1. 关闭答案，手写快照与活跃状态的数据流，并证明修改其中一个不会偷偷改变另一个。
2. 实现唯一匹配：零条、多条、同条多次都拒绝；把最长前缀匹配当成错误方案解释。
3. 把两项操作组成批次，故意让第二项失败，证明第一项没有泄露到最终状态。
4. 设计一个离线历史检索器，仅用自编虚构对话。返回 session_id、message_id、内容和来源，
   然后实现按 id 阅读邻近消息。此项为待完成作业，不是当前实验功能。
5. 加一个过期事实，例如旧目录已迁移。让查询同时命中新旧内容，说明怎样根据明确修正与时间判断，
   并在证据不足时报告未知。

## 记忆评测不能只问“记住了吗”

准备 12 条虚构事实：4 条稳定偏好、4 条会后需要查历史的细节、2 条后来被修正的事实、
2 条不应变成长期记忆的临时信息。真实学习时可扩充，不要输入密钥或真实敏感信息。

| 对照条件 | 需要控制 | 记录 |
| --- | --- | --- |
| 无长期记忆 | 同一新会话问题与模型 | 正确回答、承认未知、错误编造 |
| 仅精选小记忆 | 同样事实与固定字符预算 | 有效事实命中、旧事实误用、输入长度 |
| 小记忆加历史检索 | 同样任务、模型和总调用预算 | 召回证据、最终答案、调用数与耗时 |

分别计算：应保存事实的保留率、召回证据的相关性、更新后旧事实误用次数、
最终答案正确率、无依据断言次数，以及前台加后台总成本。
保存率高而答案仍错，不能称“记忆机制有效”；所有原文都塞进提示词也不等于高效长期记忆。
离线规则实验验证程序约束，真实模型实验才能观察模型是否选择正确写入与使用召回。
当前这三组真实实验都尚未运行。

## 口头验收与现场修改

不用讲义回答：

- 为什么记忆不会直接进入模型权重？它怎样影响回答？
- 为什么保存在文件里仍可能在当前会话不可见？压缩边界有什么例外？
- 为什么 patch 比整条 replace 更适合更新多事实条目？
- 为什么没有 read 动作仍不等于不能读取历史？
- FTS5、trigram、向量检索分别解决什么，中文短词会遇到什么问题？
- 为什么收到 staged success 还要等批准？
- 为什么文件锁不能阻止两个 Agent 在语义上污染共同记忆？
- 为什么 provider 超时不等于线程被杀？为什么会话 end 必须先于 switch？
- 如何证明一条错误来自存储、检索、上下文构造还是模型使用？

现场修改：为离线实验加入“条目来源 id”，让 patch 保留原来源，并补一项能发现来源丢失的测试。
能自己解释、改动和发现反例后，再登记本专题通过；目前学习者状态为待学习。
