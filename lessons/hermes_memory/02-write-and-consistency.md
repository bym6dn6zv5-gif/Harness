# 第 2 课：一条记忆如何安全地落盘

## 谁写文件

模型产生 memory 工具调用；程序验证和执行。
在本次版本中，模型可用的操作是 add、patch、remove，也可以在同一个 target 上提交 operations 批次。
没有 read 动作：启动时已注入小型文件记忆；session_search 是另一种读取历史的工具。
顶层 target 明确选择 memory 或 user。缺失或不一致的 target 会被工具边界拒绝。
Python 函数签名的默认值与对模型暴露的 schema 是不同层，不能只看默认参数推断 API 允许省略。

~~~json
{"target": "user", "action": "add", "content": "偏好通俗中文，先讲数据流再讲术语"}
~~~

以下为调用形状示例，不会在你的机器上执行真实记忆写入。

## patch 为什么取代 replace

原条目：“项目在 D 盘，使用 Python 3.14，每天学习两小时。”
如果模型只想更新版本，整条替换容易误删路径与学习时间。
本版本的 patch 只改一个明确片段：

~~~json
{"target": "memory", "action": "patch", "old_text": "Python 3.14", "content": "Python 3.15"}
~~~

这只是说明局部替换，不能当成你已安装 3.15 的事实。
定位规则先考虑整条精确匹配，再考虑子串：匹配零条或多条要拒绝；
同一条内出现多次 old_text 也拒绝，要求更明确的上下文。
replace 已从模型工具动作中移除，调用会报错指向 patch。
MemoryStore 内仍保留 replace 等兼容处理，用于旧的待审批写入；内部方法存在不表示模型现在应该调用。

## 容量与批次

当新增或修改后的内容超过容量，写入返回错误，不会静默删除旧条目，也没有自动压缩小文件的保证。
可以缩短内容，或把删除过时条目与新增事实放在一个 operations 批次中。

~~~json
{"target": "memory", "operations": [
  {"action": "remove", "old_text": "已废弃的项目目录"},
  {"action": "add", "content": "当前项目路径应在工作区核验"}
]}
~~~

MemoryStore._batch 先在副本上逐项应用，检查最终容量，然后一次提交。
中间任一操作无效或最终超限，整批不写入。
还有一个容易遗漏的保护：原本非空的存储不能通过批次删除成空；明确删除最后一条有单独 remove 路径。
批次的“一次提交”是本地这份文件的语义，不是跨 provider 的分布式事务。

连续整理失败还有每回合重试限制，避免记忆整理把用户回答的预算耗光。
成功后返回 done 等终止信息，提示模型继续用户任务。

## 写入的关键边界

读 tools/memory_tool_store.py 的 _mutate（338 起）：

1. 获取文件锁。
2. 从磁盘重新读取；已经存在但不可读时拒绝覆盖。
3. 解析条目并在需要的操作上检查特殊的外部格式漂移。
4. 在新读到的数据上运算和检查。
5. 通过临时文件与替换完成写入，返回结果。

锁减少并发写入丢失；锁内重读防止拿旧列表覆盖新条目；
临时文件替换减少读者看到半个文件的风险。这三个动作分别解决不同问题。
它们不意味着两个 Agent 共用一个 home 的记忆在语义上不会相互污染。
官方建议多个 Agent 使用各自 profile。

不要把外部漂移检查讲成通用 CAS。此版本 _detect_external_drift 的核心信号是解析出的单条文本超过整份文件容量，
用于发现可能被错误拼接的自由文本；它并不比较所有外部变更的版本号。
第 9 天 SQLite revision 的比较交换是另一个机制。

## 写入许可

默认 write_approval 为 false。开启后，交互 CLI 的前台写入可以现场提示，
网关、脚本和后台复盘等路径会暂存待审写入。
“已暂存”不同于“已保存进 MEMORY.md”。查看 pending 与真正批准是两个事件。

即使全局审批关闭，无人值守后台复盘中的 patch/remove 也会走专门的暂存门；
add 可以继续，但仍受内容与容量等检查。
待审修改会固定目标的完整条目，批准时如果条目已变化，要拒绝旧提案，不能用旧子串误改新内容。

验收反例：

- 两条都包含“Python”，模糊 patch 必须不写入。
- 批次先删一条，下一步找不到目标，原文件必须完整保留。
- 内容超限必须不写入，也不能无限整理重试。
- staged 返回 success 字段仍不能当成落盘成功，必须检查 staged/proposal_staged。
- 后台写入不能绕过前台才有的审批门。
