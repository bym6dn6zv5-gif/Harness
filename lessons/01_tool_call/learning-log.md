## 问答与澄清

### 谁真正打开文件

学习者最初回答：“是模型调用工具打开的。”

进一步区分：模型提出工具名和参数；Harness 中的 Python 执行程序校验请求并打开文件；
工具结果再交回模型。实际读取发生在 `target.open("rb")` 和后续的读取操作。
本课的模型回复是预先写好的模拟回复。

### 请求未知工具会怎样

学习者回答：“返回错误。”

本实验返回 `unknown_tool`。执行程序只支持已提供的 `read_file`，不会执行未知工具名。

### `path` 传入数字 123 会停在哪里

学习者回答：“校验参数。”

本实验要求非空字符串，错误类型会返回 `invalid_arguments`；此时没有打开文件。

### 只检查错误返回值，能否发现先读文件再报错

学习者判断：“应该不能（我不清楚）。”

这个方向正确。假如只检查最终错误码，某个实现即使先发生了读取，再返回相同错误码，
测试也可能通过。因此当前测试还在运行期间临时替换 `open()`：一旦执行到文件打开，
就抛出 `AssertionError`。在当前实现下，这能检查错误参数场景是否触发了文件打开。

这项检查针对本实验的特定文件打开路径，不构成对所有读取方式或所有副作用的完整证明。
需要继续掌握的点：返回值检查与执行过程检查分别能发现什么问题。
