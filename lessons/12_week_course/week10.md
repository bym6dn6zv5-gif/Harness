# 第 10 周：用真实源码校准自己的设计，并接入一个 MCP 工具

[回学习时间表](../../docs/study-calendar.md#w10) · [上一周](week09.md) · [下一周](week11.md)

本周主教材任务：主路径整合、MCP 与 provider。按 [源码任务表](../source_mastery/curriculum-map.md) 对照 claw-code 与 Codex，
先读 [主讲义](../source_mastery/README.md)，再提交本周 Python 实现与一个失败反例。

周成果：三份指定版本的源码笔记，一个只读 MCP 工具接入实验。
不要求读完三个仓库，也不把别人的规模和成绩当成自己的成果。

<a id="w10-d01"></a>

## 第 1 天：建立源码阅读方法

先读 [资料索引](sources.md)，为仓库记录地址、commit、文件、符号和阅读日期。
一次追一条数据流：输入从哪里来，经过哪些转换，哪里执行，结果回到哪里。
用“原项目观察 / 我项目对应 / 尚未确认”三栏记笔记，避免看到相似名字就推断实现一致。
验收：给出一条可重新定位的笔记，代码版本不写 main 代替。
基础：调用栈与模块依赖图。

<a id="w10-d02"></a>

## 第 2 天：Codex 工具路由

沿用九天教材中的固定提交，查找 build_tool_call 与 dispatch_tool_call_with_code_mode_result_inner。
画出外部响应字段、内部调用对象、invocation、registry 的关系；只解释实际读到的分支。
与自己的 ToolRegistry 比较：工具名如何找处理器，调用上下文如何传入，结果怎样关联。
验收：能指出一个教学简化和一个值得借鉴的设计，不推断桌面或云产品的全部实现。
基础：Rust 的 struct、enum、Result 只学本片段用到的部分。

<a id="w10-d03"></a>

## 第 3 天：claw-code 循环与权限

从本机固定提交的 run、dispatch_tool、enforce_tool 跟踪一次 read_file。
检查调用方是否传入 enforcer、当前模式怎样处理，而不只看 PermissionEnforcer 的名字。
对照循环上限、messages.push 和工具结果 id；把模式与当前教学名称许可的差别记下。
验收：一页图加三个符号定位；没有修改教材仓库。
基础：可选参数为何影响实际约束？

<a id="w10-d04"></a>

## 第 4 天：mini-swe-agent 的模型与环境边界

先选择并记录一个 commit，再根据该版本目录定位 Agent、模型、执行环境；不同版本目录可能变化。
跟踪一次回复如何变成动作、动作如何进入环境、观察如何回到历史。
比较自己的固定工具接口与该版本动作格式；不要因为项目较短就省略执行边界分析。
验收：写出自己的循环能对应什么、还没有实现什么。资料：[项目官方文档](https://mini-swe-agent.com/latest/)。
基础：抽象接口如何让模型和执行环境分别替换？

<a id="w10-d05"></a>

## 第 5 天：MCP 最小实验

MCP 连接工具与应用，不能代替任务循环、许可、预算或外部评分。
按 [官方规范和 Python SDK](sources.md) 选择并锁定兼容版本，先用 stdio 只接一个固定 `course_note` 工具，
返回教材中的一句话，不接个人目录，不自动下载或运行陌生服务器。
实现目标流程：初始化 → 列出工具 → 校验参数并调用 → 把结果转成内部工具结果。
用确定性客户端测试无参数调用、未知工具、坏参数和服务器断开；诊断日志写 stderr，协议输出保持干净。
验收：展示真实协议往返；单纯包装一个 Python 函数并不能算已接入 MCP。
基础：JSON-RPC 请求 id、通知与响应。

<a id="w10-d06"></a>

## 第 6 天：接回自己的 Harness

在工具执行器外加 MCP 适配器，许可通过后才发起调用；处理连接超时、错误和返回内容上限。
比较本地 handler 与 MCP handler 的共同内部结果，原循环不应关心传输细节。
把进程启动、关闭、失败清理写入实验记录；SDK 安装或服务器运行尚未完成就标未验收。
验收：同一条只读任务可通过 MCP 返回结果，断开后正常停止。
基础：协议标准化与业务策略的职责划分。
