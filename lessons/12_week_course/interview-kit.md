# 项目讲解、现场改动与简历模板

## 10 分钟讲解

| 时间 | 讲什么 | 必须有的证据 |
| --- | --- | --- |
| 0—1 分钟 | 输入、目标、能解决的任务范围 | 一条具体任务 |
| 1—3 分钟 | 模型请求、工具执行、结果回传、停止 | 自己的数据流图与调用 id |
| 3—5 分钟 | 参数、工作区、超时、恢复与预算 | 一个失败轨迹和处理代码 |
| 5—7 分钟 | 任务集、外部评分与对照实验 | 原始结果表与版本 |
| 7—9 分钟 | 两项改进、取舍与剩余问题 | 变好及变差的案例 |
| 9—10 分钟 | 下一步改进和适用边界 | 有根据的优先级 |

## 追问

1. 模型说完成了，为什么不能直接记成功？
2. schema 已写了类型，为什么程序还要验证？
3. 注册工具与允许执行有什么区别？
4. 进程超时后是否所有子孙进程都消失了？
5. SQLite 事务提交成功是否意味着文件补丁和远端费用也原子提交？
6. 如何区分工具重放与已保存历史的重复显示？
7. 字符数、token 数、上下文窗口、API 费用怎样区分？
8. 为什么 20/10 固定划分后仍可能发生保留集泄漏？
9. Hermes 的小文件记忆、session_search 与压缩摘要怎样协作？
10. Codex 与 claw 的工具结果 role 为什么不同，什么约束仍相同？

每题先讲本项目事实，再讲原项目观察。不会的分支说明下一步如何验证，不编造内部实现。

## 现场改动候选

抽一题，先描述约束，再在 30—45 分钟内实现并说明测试：

- 增加一个受限的只读工具，拒绝未知参数和越界路径。
- 增加一种终止原因，并保证恢复后预算不重置。
- 给上下文摘要增加证据 id，失效 id 返回明确错误。
- 给记忆 patch 加来源字段，保证局部修改不丢来源。

## 简历表达模板

“独立实现 Python 编程 Agent Harness，包含 ______；
构建固定 20/10 划分的 30 个微型修复任务，通过工作区外测试评分；
在 ______ 模型与 ______ 预算下比较 ______，
外部通过次数从 ______/______ 变化到 ______/______，记录 ______ 类失败。”

只有实际实现并有记录的部分才填写。没有真实模型实验时，应写“完成模拟接口与执行约束实验”，
不要填参考答案的成绩。源码学习可以写具体阅读与复现内容，不能把整份 Codex 的能力当成自己的成果。
