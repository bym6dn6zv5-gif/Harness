# 第 4 周：定位、修改、测试的隔离闭环

本周主教材任务：实际执行环境、工作区和超时入口。按 [源码任务表](../source_mastery/curriculum-map.md) 对照 claw-code 与 Codex，
先读 [主讲义](../source_mastery/README.md)，再提交本周 Python 实现与一个失败反例。

周成果：在独立的小型仓库副本里应用补丁并执行测试，保留基线版本和完整 diff。
这是首次运行会修改文件或执行任务代码的工具，先限定操作范围。

## 第 1 天：创建一次性任务工作区

用课程任务准备器创建一个开发任务，或复制你自己的最小 Python 仓库；不要把主项目当作 Agent 修改目标。
记录起始文件指纹和初始测试失败。基线源码、日志与输出文件分开放，恢复或清理只针对确切任务目录。
验收：能列出本次允许修改的文件，主项目源码没有变化。
基础：进程工作目录与 Python 模块导入路径。

## 第 2 天：先做受限补丁工具

第一版采用结构化“文件、预期旧内容、替换内容”，限定 UTF-8 文件和工作区内路径。
要求旧内容恰好命中一次，否则返回 `patch_conflict`；先构造全部新内容，通过校验后再写单文件。
记录写前和写后指纹及 diff。多文件原子事务留待扩展，不假装一次写一半也算成功。
小例子：把 `return text[0]` 改成空字符串时返回 None，再保留非空分支。
验收：成功、未命中、多次命中、越界和已变化文件均有测试。基础：临时文件与 replace。

## 第 3 天：测试工具的输入不是任意命令

先把工具参数收紧为已知测试目标，不让模型自由拼 shell。工具输出包括退出码、耗时、stdout/stderr 摘要与截断标记。
只在准备好的执行环境中使用固定参数列表启动 pytest。空测试集、导入错误、断言失败要分别识别。
验收：一个通过测试、一个断言失败、一个导入错误均可解释。
基础：退出 0 与 pytest 其他退出码的含义，查官方文档后记入笔记。

## 第 4 天：超时与清理

复盘第 8 天固定子进程实验，再为测试执行器增加超时。
容器执行超时后要停止指定容器并等待清理；仅结束本地 docker 客户端不等于容器已停止。
用自己写的有限等待测试观察，保留容器 id 与停止证据；不要运行无限派生进程等破坏性实验。
验收：超时有明确状态，下一任务能正常启动，残留容器检查清楚。
基础：父子进程与进程树。

## 第 5 天：Docker 执行环境

先只检查 Docker 是否存在和服务是否运行，缺失时记录并在聊天中决定安装；备课不会自动安装。
参考 [Docker 官方运行文档](https://docs.docker.com/engine/containers/run/) 配置独立网络、只读根文件系统、
资源上限和挂载。只把任务目录设为可写，评分材料另挂只读；不挂密钥、主仓库或 Docker socket。
镜像提前安装测试依赖，执行任务时不临时联网安装。记录实际 image id，别只记一个会变化的 tag。
验收：输入输出目录、权限与资源配置可说明；尚无 Docker 时只做设计，不在宿主执行生成代码。
基础：镜像与容器的区别。

## 第 6 天：串起一次闭环

先用回放模型确定性地“搜 → 读 → 补丁 → 运行公开测试 → 回答”，再尝试真实模型。
模型客户端留在宿主，执行环境只收到任务文件和测试参数。
报告修改文件、diff、测试摘要、停止原因；把仍未验证的地方写出来。
验收：保存改前失败、改后通过、补丁内容和原始轨迹，创建可复现基线提交。
基础：为什么通过一个公开测试不能推出所有边界正确？

## 第 7 天：周验收

由我换一个开发任务，你展示从干净副本开始的完整修复；测试超时或补丁冲突时能说明原因。
通过条件：工具受限、执行隔离、修改可追踪、结果有测试证据。环境未就绪则本周未通过，不跳过隔离要求。
聊天入口：“第 4 周，我的容器挂载和补丁记录是……请检查边界。”
