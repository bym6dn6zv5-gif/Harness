# Mini Coding Harness 的工程契约

这是后续项目的设计与验收约定。现有 lesson 模块各自展示一部分能力，不等于全部契约已经实现。

## 一次运行的输入输出

输入：独立任务副本的绝对路径、问题描述、模型配置、工具许可、次数/时间/费用预算。
输出：修改补丁、公开测试结果、事件轨迹、检查点、运行状态；评分器另给外部通过与失败原因。

建议将“运行停止”和“任务得分”分成两个字段：

| 字段 | 约定 |
| --- | --- |
| status | model_finished、failed、budget_exhausted、interrupted 等停止状态 |
| stop_reason | step_limit、tool_timeout、invalid_response、permission_denied、workspace_conflict 等具体原因 |
| passed | 外部评分后才有 True/False；未评分为 null |
| model_calls | 已记录的模型请求尝试，最终回复也计一次 |
| tool_attempts / tool_executions | 请求尝试与实际进入 handler 分别计数 |
| usage / cost | 有来源的测量或结算；未知为 null，不能用 0 替代 |

第一批 lesson 使用 `step_limit` 等直接状态是教学简化；接入完整项目时提供明确映射，保留兼容说明。

## 消息与调用标识

内部请求形状：

```json
{"role":"assistant","tool_call":{"id":"c1","name":"read_file","arguments":{"path":"task.py"}}}
```

内部结果形状：

```json
{"role":"tool","tool_call_id":"c1","content":"{\"ok\":true,\"data\":{\"content\":\"...\"}}"}
```

一个工具请求对应一个结果。id 必须存在且满足本运行的唯一性约定。
解析错误在执行之前停止；工具的预期错误仍用对应 id 回传。完整接口与供应商协议由适配层转换。

## 工具边界

| 工具 | 最小参数 | 输出要点 | 重点拒绝条件 |
| --- | --- | --- | --- |
| read_file | 相对路径，可扩展行范围 | 路径、片段、原长度、截断标记 | 越界、非文本、过大、不合法范围 |
| search_code | 字面查询、限定范围、命中上限 | 相对路径、行号、有限片段 | 空查询、越界、无界遍历 |
| apply_patch | 文件、预期旧内容、替换内容 | 前后指纹、diff、修改文件 | 不唯一命中、内容冲突、越界 |
| run_tests | 已知测试目标，不接任意命令 | 退出码、耗时、摘要、超时/截断 | 未许可目标、环境缺失、超时 |

执行入口先检查任务许可，注册表负责参数，具体工具负责路径和执行约束。
容器只接触任务副本；模型密钥留在宿主。评分代码不在 Agent 可修改目录中。
文件许可不能替代系统隔离，容器也不等于无限制地接受任何宿主挂载。

## 循环不变量

1. 每次请求前检查剩余预算和中断标记，不能先请求后判断超额。
2. 每个已执行工具都有 id、结果和事件；错误不能伪装为空的成功结果。
3. 最终文字结束的是模型循环，外部评分仍然独立。
4. 同一任务不会因 resume 获得一套全新预算。
5. 已结束任务再次 resume 不重复执行；配置或工作区冲突停止说明。

用模拟模型覆盖正常、无限重复、重复 id、坏回复、坏参数和错误后继续。
这些检查验证 Harness 逻辑，不衡量真实模型能力。

## 状态与副作用

检查点包含版本、任务标识、消息、配置指纹、工作区清单、预算账本、状态和最近完整操作。
SQLite 更新带 revision，恢复只使用约定版本。任务操作与数据库提交的中断窗口必须写进说明。
只读调用可以重做；写入要核对操作 id 与前后状态；结果未知时宁可停止报告，也不假装恰好执行一次。

严格成本控制要求调用前预留、调用后结算、结果未知保留额度，并用服务商账单对账。
若没有可靠的单次上界和服务商硬限额，不能宣称本地估计绝不超额。

## 最低故障矩阵

| 注入情况 | 预期证据 |
| --- | --- |
| 参数错误 | handler 没有执行，结构化反馈 |
| 工具超时 | 明确停止和清理记录，副作用是否完成仍据证据判断 |
| 网络/限流 | 有界重试，每次尝试可追踪 |
| 重复动作 | 策略触发位置可定位，没有无限循环 |
| 恢复冲突 | 新调用前停止，不覆盖用户修改 |
| 预算耗尽 | 正常停止，保留已有记录和未完成状态 |
| 外部评分失败 | 模型结束与任务失败分别保留 |
| 评分环境错误 | 与补丁不正确分开报告，不静默删行 |

这一页是周验收的依据。每项是否已实现，填进自己的架构说明，不因教材里写了就标完成。
