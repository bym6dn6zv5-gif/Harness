# 第 2 周：把模型请求变成可控制的工具接口

本周主教材任务：工具 schema 与具体执行分支。按 [源码任务表](../source_mastery/curriculum-map.md) 对照 claw-code 与 Codex，
先读 [主讲义](../source_mastery/README.md)，再提交本周 Python 实现与一个失败反例。

周成果：只读 `read_file` 与 `search_code`，统一描述、参数模型和结构化结果。
参考第 2 天注册表与第 7 天许可实验。真实服务商尚未选择时一直使用模拟模型。

## 第 1 天：消息不是任意拼接的字符串

小例子：请求 `{id: c1, name: read_file, arguments: ...}` 对应反馈 `{role: tool, tool_call_id: c1, content: ...}`。
整理内部消息类型：用户、助手文本、工具请求、工具反馈。画出允许的顺序，写一组包含坏 id 的例子。
不要把本课自定义格式直接当成某个服务商的 API 格式。
验收：能在记录中一一配对请求与结果。基础：列表顺序为什么影响模型看到的上下文？

## 第 2 天：参数模型与工具描述

用第 2 天 `PathArgs` 比较手写检查与 Pydantic；观察严格类型、额外字段和空白校验。
自己给搜索参数设计 `query: str`、`max_results: int`，要求非空查询、结果上限在 1—50，拒绝 bool。
生成描述给模型看，再证明分发入口仍然执行校验。
验收：正常、缺字段、错类型、未知字段、超上限都有反馈；坏参数不进入 handler。
基础：函数对象与调用函数的返回值有什么区别？

## 第 3 天：工作区边界

复用第一课路径处理，列出 `note.txt`、`../secret.txt`、绝对路径、符号链接或目录联接四种输入。
只在自己创建的临时目录构造越界案例，不读取真实个人文件。
保留解析后的路径检查、字节上限、UTF-8 错误；记录链接和并发改动尚存的边界。
验收：越界不读取，过大文件不把全文塞回上下文。
基础：路径拼接和路径归一化为什么不同？

## 第 4 天：实现 search_code

先用 Python 逐行搜索字面量，不调用任意 shell。只遍历工作区内的普通文本文件，
排除 `.git`、`.venv`、运行记录与评分目录；限制文件数、单文件字节数、命中数和返回总字符。
每条命中包含相对路径、行号、片段；截断时返回 `truncated: true`。
小例子：搜 `parse_date` 应返回 `task.py:4` 的相关行，搜不到返回空列表而非错误。
验收：命中、无命中、截断、非法参数和越界链接都有检查。基础：遍历的时间复杂度。

## 第 5 天：模型客户端适配层

内部目标接口是 `reply(messages, tools) -> assistant_message`。先写两个离线替身：正常工具请求、坏 JSON。
适配层负责把服务商响应转成内部类型，并归一化用量；循环不直接依赖供应商字段。
如果准备真实调用，先选可访问服务，核对其官方工具调用文档、价格和限额，再添加单一适配器。
本周真实调用可选；未知价格或没有预算控制时继续 mock，不填造 token 或成本。
验收：替换客户端不需要重写工具。基础：HTTP 状态码、请求超时与 JSON 解析错误分别在哪层出现？

## 第 6 天：契约检查

整理一张输入与结果表，至少覆盖读成功、搜索命中、搜索空结果、参数错误、未知工具、越界、截断。
先用假客户端回放两个工具请求，确认每个工具结果与调用 id 对应。
不要把“模型口头说看过文件”当作执行证据，去找 handler 和结果记录。
验收：两个只读工具可调用，注册与许可职责清楚；完成一页接口说明。
基础：JSON Schema 与运行时验证各负责什么？
