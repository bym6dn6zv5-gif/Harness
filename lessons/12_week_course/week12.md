# 第 12 周：把做过的项目讲清楚

[回学习时间表](../../docs/study-calendar.md#w12) · [上一周](week11.md) · [结课进度](progress.md)

本周主教材任务：关闭教材讲解并现场修改。按 [源码任务表](../source_mastery/curriculum-map.md) 对照 claw-code 与 Codex，
先读 [主讲义](../source_mastery/README.md)，再提交本周 Python 实现与一个失败反例。

周成果：10 分钟讲解、架构说明、独立现场修改、真实项目简历和一次完整模拟面试。
不要求编造生产规模或把教学测试成绩称为实际业务收益。

<a id="w12-d01"></a>

## 第 1 天：整理架构和证据

按 [架构模板](architecture-template.md) 画模型客户端、循环、工具执行器、状态存储、评测器。
用一个真实 run_id 串起请求、补丁、测试和停止状态；再选一个失败作对照。
每个设计选择写一个备选方案和取舍，如 SQLite 与 JSON 文件、固定工具与任意 shell。
验收：图中每条箭头在代码或记录中能找到对应。基础：接口边界与模块依赖。

<a id="w12-d02"></a>

## 第 2 天：10 分钟项目讲解

按 [面试练习](interview-kit.md) 的时间分配试讲：问题、数据流、可靠性、实验、局限。
录音或计时，把背景介绍压缩，把真正做过的循环、恢复和评测讲具体。
小例子：展示一次输入冲突为何停止，比只说“支持持久化”更有证据。
验收：10 分钟内完成，能指出代码入口和一条实际结果。
基础：把技术名词翻译成用户能观察的行为。

<a id="w12-d03"></a>

## 第 3 天：代码追问

从 [问答清单](interview-kit.md) 随机选 8 个问题，先口头回答，再指向代码或测试。
核心问题包括最终回答是否占预算、超时后是否重试、写后中断怎么办、评分为何在工作区外。
回答不知道时说清已知边界和下一条验证动作，不用术语绕开问题。
验收：至少循环、恢复、评分三项能不看答案独立解释。
基础：复杂度、HTTP、进程、线程和数据库轮换复习。

<a id="w12-d04"></a>

## 第 4 天：现场修改

随机选择一个小功能，先说接口变化与验证，再在 45 分钟内实现：搜索结果分页、增加停止原因、
显示一个用量缺失告警，或为恢复新增一项配置冲突检查。
允许查标准库文档，核心判断自己完成；功能不能通过扩大工作区权限或跳过评分来实现。
验收：展示修改前失败、修改后通过和兼容性；未完成就报告差在哪里。
基础：小改动的回归范围如何确定？

<a id="w12-d05"></a>

## 第 5 天：写简历

只填写实际实现的能力、使用的数据和可复算的指标。写清“教学项目”“小型 Python 任务集”等范围。
例如“实现受限工具循环与 SQLite 恢复；以固定开发集比较两项策略；保留外部评分和失败轨迹”。
如果真实模型评测未完成，就不填写通过率提升；没有生产用户就不写业务落地或大规模并发。
验收：每句都能对应提交、报告或讲解，去掉空泛的“精通 Agent 全栈”。
基础：指标的绝对变化与相对变化。

<a id="w12-d06"></a>

## 第 6 天：模拟面试与交付

流程：10 分钟讲解、15 分钟追问、30 分钟现场修改、10 分钟复盘。可以分成两段完成。
检查主入口、环境说明、离线演示、正式结果、已知问题、源码笔记和运行约束。
给剩余问题排顺序，按目标岗位补算法、系统和工程协作，不默认转入多 Agent 扩展。
验收：四项最终成果可打开、可运行、可复算、可解释；未达标部分有明确计划。
基础：工程证据为何比框架名更有说服力？

<a id="w12-d07"></a>

## 第 7 天：结课验收

使用 [最终清单](interview-kit.md) 逐条核对，不按教材页数判断是否结课。
通过条件：独立循环、排错演练、固定任务评测、两个对照改进、10 分钟讲解及小型修改均有证据。
如果有缺项就保留未完成状态。聊天入口：“第 12 周，我准备答辩，请从我的真实项目中随机追问”。
