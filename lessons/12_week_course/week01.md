## 第 1 天：认清目录和解释器

概念：Python 是解释器，项目目录存代码，虚拟环境保存这个项目的依赖。
在 PowerShell 进入 `D:\python\File of python\Harness开发`，运行 [操作约定](lab-guide.md) 的版本检查。
比较 `sys.executable` 与终端里的 Python 名称，解释为什么使用 `.venv\Scripts\python.exe`。
把路径、版本、已确认和未确认信息记入学习日志，不因缺少软件自行安装。

验收：能指出代码和解释器分别在哪里。基础练习：相对路径 `.`、`..` 与绝对路径各举一例。
卡住时先检查当前目录，而不是反复安装 Python。

<a id="w01-d02"></a>

## 第 2 天：Git 记录一次变化

概念：工作区是文件现状，暂存区是本次准备保存的内容，提交是版本快照。
先运行 `git status --short`，在自己的学习日志中写一句理解，再用 `git diff` 找到这处变化。
只暂存这份日志，用 `git diff --cached` 复核后提交；推送前再次确认没有密钥或运行数据。
不要对不认识的改动使用重置或清理命令。

验收：能展示一条只包含日志的提交，解释提交和 GitHub 推送的区别。
基础练习：为什么 `.venv` 和 `.env` 不应放进仓库？

<a id="w01-d03"></a>

## 第 3 天：JSON 是传输格式，字典是运行时对象

小例子：

```python
import json
request = {"id": "c1", "name": "read_file", "arguments": {"path": "note.txt"}}
wire = json.dumps(request, ensure_ascii=False)
assert json.loads(wire) == request
```

把 content 中含中文、引号、换行的结果做一次往返。故意删除一处 JSON 引号，捕获解析错误。
观察 `\n` 在 JSON 文本和 Python 字符串里的差别，不要手拼多层转义。
验收：往返值相同；坏 JSON 得到清楚错误。基础练习：列表、字典、字符串各怎样序列化？

<a id="w01-d04"></a>

## 第 4 天：类型提示与运行时检查

概念：`path: str` 便于阅读，但不会自动把运行时整数挡住。参考第一课的条件检查，
为缺少 path、path=123、空白字符串和额外字段写预测，再运行原有测试。
用返回值表达预期的工具错误；对程序自身的错误保留异常堆栈，避免一个宽泛 except 掩盖全部问题。

验收：参数无效时没有打开文件。基础练习：写一个返回结构化错误的小函数，比较 return 与 raise。
提示：先看参数，再进入读取分支。

## 第 5 天：理解测试观察什么

打开 `test_lesson01.py` 中的参数错误测试，观察 monkeypatch 如何替换文件读取行为。
做一个有调用列表的假函数：如果被执行就 append。测试既判断错误码，也判断列表为空。
自己增加一个真正补足边界的案例，例如只含制表符的 path，而不是逐行照抄实现。

验收：解释“先读后报错”为什么能骗过只检查错误码的测试。
基础练习：pytest 的断言、fixture 和参数化分别做什么？
