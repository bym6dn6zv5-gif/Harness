# 第 8 周：用固定任务和外部测试评分

[回学习时间表](../../docs/study-calendar.md#w08) · [上一周](week07.md) · [下一周](week09.md)

本周主教材任务：相邻测试、评分边界与任务材料。按 [源码任务表](../source_mastery/curriculum-map.md) 对照 claw-code 与 Codex，
先读 [主讲义](../source_mastery/README.md)，再提交本周 Python 实现与一个失败反例。

周成果：30 个小任务固定为 20 开发 + 10 保留，批量运行并得到可追溯的逐任务结果。
课程提供 [任务材料](task-catalog.md)，它是教学用小函数修复集，不是 SWE-bench 或招聘统一标准。

<a id="w08-d01"></a>

## 第 1 天：任务规格

一个任务包含起始源码、问题描述、可修改范围、公开测试、外部评分和预算。
先准备 T01，解释空输入应该返回什么、哪些行为还需保持；用未经修改版本确认确实存在失败。
检查参考答案通过评分只是材料校准，不是 Agent 解题结果。
验收：同一个任务能从相同起点重复创建，新工作区不会复用上次修复。
基础：fixture 与测试 oracle。

<a id="w08-d02"></a>

## 第 2 天：冻结划分

T01—T20 为开发集，T21—T30 为保留集；记录材料版本和 manifest 指纹。
开发期只看开发集轨迹、调策略。保留任务的源码、评分与答案不送入调参提示或检索范围。
教学仓库内材料可见，所以“保留”是实验使用约定，不冒充保密测试。
验收：批量入口默认 dev，访问 holdout 需要明确选择；不存在重复 id 或划分重叠。
基础：过拟合与数据泄漏。

<a id="w08-d03"></a>

## 第 3 天：外部评分

Agent 自己运行的是公开测试；最终评分由宿主在 Agent 停止后启动独立执行环境。
评分测试放在 Agent 工作区外，并以只读方式提供给评分容器；评分前后核对材料指纹。
只有外部测试全部通过才设 passed=true，模型宣称完成不能改变这一项。
验收：把答案改成明显错误时评分失败；Agent 修改公开测试也不能改变外部预期。
基础：测试失败与评分环境失败必须分开。

<a id="w08-d04"></a>

## 第 4 天：批量运行入口

目标 `eval` 为每个 task_id、版本、repeat_id 建独立 run_id 和干净工作区，先串行处理。
把准备、运行、评分、汇总分成函数；某个任务崩溃也要留下该行，不丢掉后续记录。
输出至少包含停止状态、外部通过、耗时、token、费用、错误分类和轨迹路径。
验收：先跑 2 个开发任务，一成一败，汇总分母仍为 2；重跑不会覆盖旧记录。
基础：任务队列与独立失败。

<a id="w08-d05"></a>

## 第 5 天：失败分类

先用模型接口、协议、规划、工具参数、上下文、环境、补丁、测试、预算、恢复十类标签。
一行可以记录主因与次因；以首个可证实偏差为起点，允许 unknown，不强迫猜模型心理。
小例子：工具返回截断，模型未重读就修改错误分支，主因可能是信息不足，但需对照轨迹确认。
验收：至少 5 个失败保留输入、轨迹、补丁和外部结果。基础：可观察事实与因果解释。

<a id="w08-d06"></a>

## 第 6 天：建立基线

冻结一个可复现实现，在 20 个开发任务上按同一模型、预算和重复策略运行。
额度不足时先用回放检查批量流程，把真实模型结果标记未运行；不要用 mock 的 100% 替代能力结果。
使用 [报告模板](experiment-template.md)，列出中断、未开始和环境错误，保留原始行。
验收：能从汇总表定位任意一行的轨迹和起始源码。基础：比例的分母与遗漏样本。

<a id="w08-d07"></a>

## 第 7 天：周验收

演示新建任务、Agent 修复、独立评分、记录失败全过程。
通过条件：20/10 划分固定，评分不可由 Agent 修改，30 个任务都有明确规格，基线数据可追溯。
聊天入口：“第 8 周，这行模型已完成但 passed=false，我从外部测试看到……”。
